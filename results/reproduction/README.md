# Reproduction on a T4

[`t4_sessions.csv`](t4_sessions.csv) compares package runs on a Colab T4 with the v3.1 notebook run that generated the
published answers (sha256 `07b3e8f6228d1608…`).

| Session | Package | Answers generated / from cache | Answers identical | Contexts identical | Fully correct (test) | Groundedness |
|---|---|---|---|---|---|---|
| 27 Oct 2026, 11:02 | 3.3.0 | 0 / 108 | 113/113 | 113/113 | 97/113 (79/88) | 0.886 |
| 27 Oct 2026, 21:18 | 3.3.0 | 0 / 108 | 113/113 | 113/113 | 97/113 (79/88) | 0.886 |
| 29 Oct 2026, 04:34 | 3.3.0 | 0 / 108 | 113/113 | 113/113 | 97/113 (79/88) | 0.886 |
| 25 Oct 2026, thinking off | 3.2.0 | 108 / 0 (a different setting) | 9/113 | 113/113 | 90/113 (72/88) | 0.927 |

**What this shows.** Package v3.2 and v3.3 rebuild exactly the retrieval of the published run for all 113 questions
on real models: the same candidates, the same reranker scores (no difference at all), the same contexts and the same
gate decisions in all four runs; produce the same prompts (every answer was found in the cache
under the same key) and give the same verdicts and groundedness in every session. The 108 answers that reach the
model are reused from the cache; the other 5 are refused by the gate. The thinking-off run is a different setting,
listed because it generated its own answers on the same retrieval.

**What it does not show.** The answers of the published configuration have not been regenerated by the package: in
all three sessions they came from the cache. Seeded sampling should give the same answers on the same software and
GPU, but that has not been tested here. The test set questions are not rewritten in these sessions (no conversation).

Rebuild: `python scripts/export_results.py reproduction <v3.1 run.json> results/reproduction/t4_sessions.csv <run.json> ...`
